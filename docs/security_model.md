# 安全模型（威胁模型）

> 适用：车端/开发机上的多进程部署。目标不是替代 Linux 安全机制，而是把
> Starletto 自身的信任边界写清楚，避免「看起来安全」的默认值。

## 1. 资产

| 资产 | 位置 | 风险 |
|---|---|---|
| 通道数据 | shm 段 | 伪造控制指令、窃取传感器/定位数据 |
| 参数与配置 | parameter/config 组件、conf 文件 | 篡改车辆参数 |
| 录制文件 | `.starrec` | 泄露数据、篡改回放证据 |
| 插件代码 | `modules/*/*.so` | 任意代码执行 |

## 2. 信任边界

- **同用户、同主机**：默认可信。Starletto 不做进程间身份认证；
  同一 uid 的进程可以读写同名 shm 段、调用服务。
- **其它本地用户**：不可信。shm 段模式为 `0600`，attach 时校验段属主 uid。
- **插件来源**：只允许模块目录内的相对路径；绝对路径、`..` 越界直接拒绝。
- **conf 文件**：视为可信输入。能改 conf 的人已经能控制进程启动参数，
  这不是运行时能防的边界。

## 3. 威胁与缓解

| 威胁 | 缓解 | 残留风险 |
|---|---|---|
| 其它用户伪造/窃听 shm | `0600` + `fstat` 属主校验 | 同用户进程仍可访问 |
| conf 指向任意 `.so` | 插件路径必须相对模块目录，拒绝绝对路径与 `..` | 模块目录可写 = 可替换插件 |
| 混入不同工具链的插件 | 工具链指纹 + `doctor --deep` | 指纹不覆盖所有编译选项 |
| 录制文件被其它用户读取 | 创建时 `chmod 0600` | 同用户可读 |
| 服务被任意本机进程调用 | 依赖 shm 访问控制（同用户） | 无鉴权，多租户不适用 |
| 崩溃后 shm 段残留 | 持有者 pid 表 + 孤儿回收 | pid 复用可能误判存活 |

## 4. 非目标

- 多用户/多租户隔离；
- 网络传输安全（当前无网络 transport）；
- 插件签名/供应链验证（当前只做路径与工具链检查）；
- 载荷加密与防篡改（record 格式无签名）。

## 5. 部署建议

1. worker 使用专用系统用户运行，安装目录与录制目录仅该用户可写；
2. 不要从可被普通用户写入的目录加载 conf 或插件；
3. 需要跨用户共享通道时，显式设计共享组/ACL 方案，不要直接放宽到 `0666`；
4. 车端对外接口（诊断/OTA）不要直接暴露 parameter 服务。
