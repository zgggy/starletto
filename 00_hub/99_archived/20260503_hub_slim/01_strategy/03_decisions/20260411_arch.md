# 架构决策（2026-04-11）

## A1: 三工程独立架构

**背景**：basement/libraries/modules 职责不同，开发节奏不同

**选项**：
1. 单体仓库统一推进
2. 三工程独立 spec、独立推进、当前只聚焦 basement

**决定**：选项 2 — 三工程独立架构
**理由**：
- basement 是底座，必须先稳定
- libraries 算法库可以并行但不阻塞 basement
- modules 业务模块变化最快，不应影响底座稳定性
- 每个工程有独立的 spec 文档跟踪进度

**影响**：
- `document/spec/workplan.md` 明确声明三工程边界
- `document/spec/basement_progress.md` 只跟踪 basement
- libraries/modules 的改动仅用于配合测试

**状态**：✅ active

---

## A2: Spec-first 开发流程

**背景**：避免"写了再想"，保证设计与实现一致

**流程**：
1. Step A：定位涉及的 spec 文件
2. Step B：在 spec 中补齐接口/语法/默认值/验收命令
3. Step C：按契约实现代码
4. Step D：运行验收命令
5. Step E：同步更新 spec 文档

**状态**：✅ active

---

## A3: Header-only 代码组织

**背景**：用户偏好 .h 文件组织代码

**规则**：
- 所有代码尽量放在 .h 文件中
- 不使用 .cc/.cpp 实现文件
- CMakeLists 已 include 项目根目录

**状态**：✅ active（user_rules §1.1）
