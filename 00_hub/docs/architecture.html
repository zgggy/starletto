设计决策 DECISIONS

四条硬约束是系统宪法：Native-only · 单进程指针传递 · 跨进程零拷贝 · Schema 统一性。下表是落地这些约束的关键取舍，登记于 design_change.md。

DECISION
CHOICE
RATIONALE
构建系统
Meson + Ninja
custom_target 声明 codegen 依赖、跨平台；生成物不入库防漂移
IDL 格式
自研 .schema
零拷贝硬约束——protobuf 不满足 inproc 指针 + shm loan/view 的统一抽象
组件交付
conf 声明 + dlopen 插件
apps 与组件解耦；doctor --deep 校验插件符号；入口 star_register_components(ComponentRegistry*)
错误模型
状态码 / 异常 分治
运行时状况（transport 失败）返回 WriteResult；编程错误（端口未声明）抛异常——消除状态码被异常化又被降级为日志的反转链
代码组织
Header-only（库层）
用户偏好 .h 组织；apps 例外——app.h 已拆 app.cc，无 header-only 理由
日志系统
自定义宏 + LoggerManager
零依赖、多 sink 可切换、禁用级别编译期消除
进程编排
fork/exec + 参数传递
简单可靠、无需守护进程；wait_all 监督退出码
